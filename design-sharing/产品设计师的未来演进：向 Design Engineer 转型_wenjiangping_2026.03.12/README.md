# 产品设计师的未来演进：向 Design Engineer 转型

## 一、分享背景

随着 **AI 编程工具的发展** 和
**企业对效率的要求提升**，传统产品设计师的角色正在发生变化。

过去的设计流程通常是：

产品经理 → 交互设计 → 视觉设计 → 前端开发

这种流程存在明显问题：

-   信息逐级传递，容易失真
-   设计与开发之间沟通成本高
-   设计稿难以完整表达真实交互
-   产品验证周期较长

同时，AI 编程工具（如 Cursor、v0.dev、Lovable）的出现，使得
**代码生产的门槛大幅降低**。

设计师不再必须完全依赖前端开发即可实现界面。

在这种背景下，行业开始出现一种新的角色趋势：

**Design Engineer（设计工程师）**

即：

> 能够同时理解用户体验与前端实现，并能直接构建产品界面的设计师。

------------------------------------------------------------------------

# 二、核心观点

本次分享的核心观点有三个：

### 1. 设计师的交付物正在发生变化

过去：

-   设计稿（Figma / Sketch）

现在：

-   高保真可运行原型
-   前端组件代码

设计师的目标正在从：

**画界面 → 构建产品界面**

------------------------------------------------------------------------

### 2. AI 正在抹平设计师与代码之间的门槛

过去设计师不写代码的原因：

-   学习成本高
-   技术门槛高
-   工具复杂

而现在：

AI 工具让代码生成方式变为：

-   写逻辑
-   写 Prompt
-   修改生成代码

这使得设计师可以：

**直接生成前端组件并参与产品构建。**

------------------------------------------------------------------------

### 3. 企业越来越需要"全链路创造者"

在当前降本增效的环境下，企业更需要：

**Maker（创造者）**

而不是：

**Planner（规划者）**

也就是说：

> 能够直接产出成果的人，比只负责规划流程的人更具价值。

------------------------------------------------------------------------

# 三、方法模型

## Design Engineer 能力模型

一个 Design Engineer 通常需要具备 **三层能力结构**：

用户体验能力\
↓\
前端实现能力\
↓\
AI辅助开发能力

具体能力包括：

### 1. 设计能力

-   用户体验设计
-   UI视觉设计
-   动效设计
-   设计系统建设

### 2. 前端实现能力

理解基本的前端技术：

-   HTML
-   CSS
-   Flex / Grid
-   JavaScript
-   React / Vue

不一定需要成为专业工程师，但需要能够：

-   理解代码
-   修改代码
-   构建组件

### 3. AI开发能力

熟练使用 AI 编程工具：

-   Cursor
-   v0.dev
-   Lovable
-   Windsurf

核心能力：

-   编写技术型 Prompt
-   调整 AI 生成代码
-   快速构建原型

------------------------------------------------------------------------

# 四、框架结构

Design Engineer 的工作结构可以拆成 **6 个核心模块**：

## 1 构建高保真原型

传统设计：

-   静态设计稿
-   Smart Animate 假交互

Design Engineer：

-   使用代码构建真实交互
-   可运行的产品原型

例如：

-   表单输入
-   动态数据
-   页面跳转
-   动效反馈

------------------------------------------------------------------------

## 2 AI产品交互验证

AI 产品具有特殊交互：

-   流式响应
-   延迟反馈
-   上下文联动

这些很难通过 Figma 模拟。

因此：

**代码原型成为 AI 产品验证的关键工具。**

------------------------------------------------------------------------

## 3 设计系统维护

Design Engineer 需要同时维护两套系统：

设计侧：

-   Figma Component

代码侧：

-   前端组件库
-   Storybook

目标：

**设计与代码统一。**

------------------------------------------------------------------------

## 4 Design Token 同步

保证设计变量与代码变量一致，例如：

-   颜色
-   字体
-   间距
-   动效

避免：

-   设计还原度问题
-   UI实现偏差

------------------------------------------------------------------------

## 5 UI细节优化

设计师可以直接在代码中优化：

-   padding
-   color
-   animation
-   easing curve

而不是：

截图 → 提需求 → 等前端修改。

------------------------------------------------------------------------

## 6 AI辅助开发

通过 AI 快速生成：

-   页面结构
-   组件基础
-   代码框架

Design Engineer 的工作是：

-   优化体验
-   调整样式
-   完善逻辑

------------------------------------------------------------------------

# 五、可复用结论

从本次分享中可以总结出 5 条重要结论：

### 1 设计师的角色正在从"设计者"变为"构建者"

未来更有价值的设计师：

**能直接构建产品。**

### 2 代码能力将成为设计师的重要加分项

并不是要成为工程师，而是：

> 能理解并修改代码。

### 3 AI工具正在成为设计师的新生产力

未来设计能力的一部分将是：

**AI协作能力。**

### 4 高保真原型将成为产品验证的关键工具

特别是：

-   AI产品
-   复杂交互产品

静态设计稿已经不足以表达真实体验。

### 5 设计行业会出现明显分化

未来设计师大致会分为三类：

1.  战略型设计师（用户研究、产品策略）\
2.  Design Engineer（构建产品、实现交互）\
3.  纯UI设计师（仅视觉设计，压力最大）

------------------------------------------------------------------------

# 六、行动建议

## 1 学习前端基础

重点理解：

-   HTML
-   CSS
-   Flex布局
-   响应式设计

目标：

能够读懂并修改代码。

## 2 熟悉组件化思维

学习：

-   React组件概念
-   Design System
-   Component设计

从：

**页面思维 → 组件思维**

## 3 掌握AI编程工具

建议重点尝试：

-   Cursor
-   v0.dev
-   Lovable

练习：

-   Prompt写法
-   生成界面组件

## 4 尝试代码原型工具

推荐工具：

-   Framer
-   SwiftUI
-   React + Tailwind

用来构建：

**真实可交互原型。**

## 5 建立工程思维

设计时思考：

-   组件复用
-   空状态
-   加载状态
-   异常状态

让设计更接近真实产品。
